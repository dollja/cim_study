# Questions to answer for each case

Use the root `REVIEWS.json` and `REVIEW_GUIDE.html`.

1. **Reviewer and exposure:** Who judged this case? What drafts, outputs, labels or later evidence had they already seen?
2. **F1 — Task question:** What one local question, task step, event and phase are shared?
3. **F2 — Speakers and wording:** Which two participants and which exact prefix spans are compared?
4. **F3–F5 — Readings and support:** What does each participant express? Which readings are only possible? What reference links, endorsements or corrections support the active reading?
5. **F6 — Task consequences:** What follows from each supported reading using the same declared task function? Which required facts are unknown?
6. **Uncertainty:** Could any unresolved support, binding, phase or alternative change the comparison?
7. **F7 — Label and reason:** Apply the same-singleton/disjoint/otherwise-unresolved rule. Explain the label using the prefix alone.
8. **Verification and selection:** What checks did you actually complete? Recommend inclusion or deferral separately from the local label, and explain why.

`null` means pending. `UNRESOLVED` is a substantive judgment. Marking an interpretation `supported` requires expressed participant evidence; a map object or bare acknowledgment alone is insufficient. Source-string validation cannot decide support for you.

For calibration, begin with MT03, MT05 and WW02 on separate copies. Compare judgments after first-pass submissions are saved. Those exercises do not automatically qualify as blind evaluation cases after discussion. Preserve exposed-development and independently reviewed conditions separately.
