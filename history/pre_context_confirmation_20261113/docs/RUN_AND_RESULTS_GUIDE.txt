What the model sees

The model receives only the request messages generated by pilot.py. The observer evidence has four fields: overall_task, participants, context_sources and dialogue_prefix. Human focus, labels, wording suggestions, selection notes and later dialogue must stay outside those requests.

The harness performs discovery (F1/F2), shared readings (F3), each participant's attribution and separate support check (F4/CHECK), then deterministic retention, task computation and comparison (F5-F7). One candidate with one hypothesis usually uses six model calls. The maximum is 46 stage calls per case. The prompt caps 20 real cases at 920 stage calls plus at most 20 transient retries, with unchanged messages and saved attempts. Returned malformed output or an unfavorable answer is not retried for a better result.

Commands already present

Run these from the project root with Python 3.10+. Replace RUN_ID, FROZEN, CASE_ID and EXACT_MODEL_ID with actual values. A frozen observer directory is required only when a new version has actually been made; use the correct existing directory otherwise. New output filenames preserve earlier records.

  python review_tools.py validate REVIEWS.json --observer-dir prospective/observer_inputs
  python review_tools.py validate REVIEWS.json --observer-dir prospective/observer_inputs --complete

The first checks the current file; the second also checks completion. An error is a reason to inspect the relevant record, not to invent a confirmation.

After two real submissions:

  python review_tools.py compare REVIEWS.json reviews/reader_2/REVIEWS.json --observer-dir FROZEN/prospective/observer_inputs --out reviews/differences_r1_r2_RUN_ID.json
  python review_tools.py adjudication-template REVIEWS.json reviews/reader_2/REVIEWS.json --observer-dir FROZEN/prospective/observer_inputs --out reviews/ADJUDICATION_RUN_ID.json

The second command prepares a blank decision ledger. Humans must resolve and record the judgments; running the command does not adjudicate anything. Preserve true exposure/history. The two r1 versions cannot satisfy the two-reader requirement. Ledger binding uses normalized review-record hashes, keeping a key-only conversion compatible with existing machine ledgers. Preserve raw submitted-file hashes separately; changed evidence or judgments need a new ledger.

After actual adjudication:

  python review_tools.py export-adjudicated REVIEWS.json reviews/reader_2/REVIEWS.json --ledger reviews/ADJUDICATION_RUN_ID.json --observer-dir FROZEN/prospective/observer_inputs --out reviews/ADJUDICATED_RUN_ID.json --allow-assisted

--allow-assisted retains the disclosed assisted-development reference condition. It does not skip evidence or human-review requirements. The ledger's evidence_review field concerns a particular actual model candidate and is completed only after its evidence chain is reviewed.
